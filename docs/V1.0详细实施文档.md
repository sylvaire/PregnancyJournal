## 1. 范围与执行约定

### 1.1 V1.0 必须完成

1. 多孕期档案、日期依据与历史修订、首页概览。
2. 产检预约、完成记录、日历、关联资料及提醒。
3. 图片/PDF 导入、系统相机拍照、排序、预览、筛选、搜索和回收站。
4. 药品、用药方案版本、实际服药记录、固定时刻提醒。
5. 体重、血压、血糖、自定义指标、备注和基础趋势。
6. 本地加密、应用锁、隐私通知、草稿恢复。
7. 坚果云连接、单主设备加密快照、完整性检查、完整恢复。
8. 本地完整加密备份、结构化数据与原始文件导出、就诊摘要 PDF。
9. 对断网、进程中断、磁盘不足、权限关闭与恢复失败提供可理解反馈。

### 1.2 明确延后

- OCR、文档自动裁边与增强、CameraX 自建扫描器。
- 多设备双向同步、记录合并、自动冲突解决、家庭账号与共享权限。
- 固定间隔服药调度、复杂自然语言医嘱解析、医学判断。
- 云端后台服务、应用注册、统计 SDK、广告及付费系统。

系统相机拍照满足首版拍摄需求；自建扫描体验属于后续增强。V1.0 中的“同步状态”统一对用户称为“备份状态”，避免暗示已提供双向同步。

### 1.3 决策与变更

产品范围以本章为准；其余章节给出默认实现决策。需要改变版本范围、安全格式、最低系统版本或恢复语义时，先记录决策原因、受影响任务与回退方案，再修改相应文档和实现。

未验证的依赖版本不进入工程配置；技术验证失败属于需要解决的任务，不得通过取消加密、跳过校验或清库规避。

包名在 P0 冻结，示例占位符不作为正式发布包名。仅给跨模块或复杂规则增加 UseCase，简单 CRUD 通过 Repository 完成。

### 3.1 依赖与状态流

`Screen → ViewModel → Repository / UseCase → DAO / FileStore / BackupCoordinator`。

- UI 使用 `collectAsStateWithLifecycle()` 读取状态；禁止直接调用网络或 DAO。
- ViewModel 暴露不可变 `UiState` 与用户事件入口，不持有 Activity、View 或界面 Context。
- 导航仅携带对象 ID，不传完整报告、凭据或大位图。
- 数据写入成功后界面通过本地 Flow 更新；后台上传失败不回滚用户记录。
- 错误归一为验证失败、空间不足、认证失败、网络失败、密钥不可用、格式不兼容等类型。
- IO、文件加密和 PDF 处理移出主线程；列表提供稳定 key，图片按目标尺寸采样。

### 3.2 进程恢复与草稿

`SavedStateHandle` / `rememberSaveable` 只保存对象 ID、滚动位置和轻量页面状态。医疗输入和附件清单写入加密草稿表，不放入可能被系统保存为明文的状态 Bundle。

草稿在编辑后短延迟持久化，离开页面时补写；成功提交后在同一事务清理。进程重建时提供“继续编辑/放弃草稿”。应用锁遮挡期间隐藏敏感界面，重新验证后恢复编辑。

## 4. 数据字典与业务约束

### 4.1 通用字段

业务表默认含 `id: UUID`、`createdAt/updatedAt: Instant`、`revision: Long`、`deletedAt: Instant?`。记录级 `revision` 每次有效修改递增。

- 纯日期序列化为 ISO `yyyy-MM-dd`；需要时刻的事件使用 Instant，并保留 ZoneId 和原始本地时间。
- 金额、剂量、健康数值使用规范十进制字符串或固定精度整数，业务计算使用十进制类型，避免二进制浮点误差。
- 枚举持久化稳定字符串，不使用序号；未知值在恢复时报告兼容性问题。
- 空值表示未填写，不使用 0 或空字符串冒充未知日期和测量值。

### 4.3 基础设施表

| 表 | 职责 |
|---|---|
| vault_state | vaultId、schemaVersion、localChangeSequence、activeGeneration |
| change_log | sequence、entityType、entityId、revision、operation；与业务变更同事务 |
| import_jobs | 源引用、暂存对象、导入状态、可恢复错误；不备份临时授权 URI |
| backup_history | snapshotId、capturedSequence、对象数、字节数、状态、完成时间、错误类型 |
| backup_state | destinationId、writerId、最后验证快照、最近尝试、失败原因 |

产品方案中的 SyncChange/SyncState 在首版分别收敛为 change_log/backup_state，不实现下载变更或设备同步游标。云端凭据进入独立加密凭据文件，不进入备份业务数据。

### 4.4 事务边界

一次业务写入同时完成实体修改、revision 递增、change_log 追加与本地全局序号递增。上传成功只更新对应快照的 capturedSequence，不能将上传期间产生的新变更误标为已备份。

数据库不与文件系统形成真正原子事务。附件通过“暂存 → 认证加密完成 → 文件原子重命名 → 数据库关联提交”协议衔接，失败对象由导入恢复任务处理。

禁止破坏式数据库迁移。每次 schema 变化提交 schema 文件、迁移说明和旧版本数据迁移测试。

## 5. 日期、状态与删除规则

### 5.1 孕周计算

有确认预产期时，以 `confirmedEdd - 280 天` 作为显示计算起点；否则使用末次月经日期。以用户所处日期计算相差天数，再拆为周与天。

无依据时显示“待补充日期”；结果小于零时显示“日期待核对”，不显示负孕周。日期异常只提示核对，不作健康判断。日期修改新增 revision；历史产检保留记录时的计算天数与依据 ID，今日概览使用最新依据。

### 5.2 状态转换

- 孕期：ONGOING → ENDED → ARCHIVED；归档可恢复到结束状态。重新开启提醒必须由用户确认。
- 产检：SCHEDULED → COMPLETED / CANCELLED；重新预约时保存变更。过期只是列表派生状态，不自动完成。
- 用药方案：ACTIVE → PAUSED / ENDED；编辑生成新版本，既往服药记录仍引用旧版本。
- 服药：未记录、已服用、已跳过；到期未录入保持“待确认”，不自动认定漏服。
- 附件：STAGING → ENCRYPTED → READY；失败为 FAILED，可重试或清除。

### 5.3 删除与回收站

默认软删除保留 30 天，并提供即时撤销。孕期整体删除影响所属记录，先显示数量与范围；恢复整体删除使用同一个删除批次 ID，不复活此前已独立删除的记录。

产检删除解除关联但保留资料；资料删除只移入回收站，不删除原相册。已被备份快照引用的云端附件不因本机删除立即清理。

当前快照保留回收站数据与关联附件；到期清理后新快照不再包含，旧快照仍可能保留。界面说明历史备份中的保留情况。“删除全部本地数据”与“删除云端备份”分开操作并要求明确确认范围。

## 7. 文件导入、预览与导出

### 7.1 导入协议

1. 系统 Photo Picker 选择图片，SAF 选择 PDF；系统相机通过受控临时 URI 返回图片。
2. 检查实际文件头、可读取性、大小和 MIME，忽略不可信扩展名与路径。
3. 流式写入应用私有暂存区并加密，计算原文与密文校验值。
4. 写入完成并认证通过后，移动到最终对象位置并提交元数据。
5. 生成受保护缩略图，清理相机原始暂存文件，界面标记 READY。

单文件大小初始上限 100 MiB，一次最多 20 项；P0 用真实大 PDF 和低内存设备验证后调整。提前检查可用空间，复制中继续处理写入失败。单项失败不抹掉已成功项，整份资料显示“部分文件导入失败”。

持久 URI 权限仅在提供方支持时申请，不依赖所有来源都允许持久授权。源权限丢失时请求重新选择。恢复导入任务按对象 ID 幂等执行，不重复创建资料。

### 7.2 预览保护

图片按显示尺寸解码；PDF 按页渲染并限制缓存。PdfRenderer 若需要可寻址明文文件，解密到私有、禁止系统备份的临时目录；页面关闭或应用锁定后关闭描述符并删除，启动时清理异常退出残留。

首版 PDF 预览不加载远程内容，不执行嵌入脚本。损坏文件保留原始归档并提供替换或导出，不导致列表崩溃。

### 7.3 输出格式

- **完整加密备份 `.pjbackup`**：可恢复、全量业务数据与所需附件，使用第 10 章版本化格式。
- **结构化数据包**：UTF-8 JSON、字段说明、原始附件和来源索引；明确提示导出后由用户保护。
- **就诊摘要 PDF**：范围、孕期信息、产检、用药、选定指标、生成时间、“用户整理记录”标记。
- **单份原件分享**：临时 FileProvider URI，最小读取授权，限制授权文件范围。

通过 SAF 写入用户选择位置。摘要使用 Android PDF 能力生成，处理分页、中文字体、长备注与空值；不得把一屏截图拉伸为整份 PDF。发送给其他应用后不能保证副本被撤回，清理只作用于本应用缓存。

## 8. 用药、健康与提醒实施细节

### 8.1 用药方案版本

`frequencyType` 首版支持 DAILY_TIMES、WEEKLY_TIMES、ONCE、AS_NEEDED、TEXT_ONLY。

固定时刻保存 LocalTime、适用星期及 ZoneId 策略；按需及纯文本不生成计划服药点。方案生效时刻之前的记录不可重算覆盖；暂停/结束取消未来提醒，已到期未确认项仍可补记。

Occurrence ID 由方案版本、计划日期、时刻、时段序号确定。重复通知、通知点击和界面操作使用同一个 ID；数据库唯一约束和事务共同防止重复服药记录。

“稍后提醒”只调整提醒触发时间，原计划服药点不变；“已服用”记录真实操作时间，用户可修正。“跳过”与“没有记录”分开表示。

### 8.2 测量与趋势

- 体重默认 kg；血压默认 mmHg，收缩压/舒张压作为同一测量组。
- 血糖默认 mmol/L，场景为 FASTING、POST_MEAL（额外记录分钟数）、OTHER；首版不自动换算混合单位。
- 自定义指标先创建名称、单位与值字段，修改单位形成新定义。
- 趋势按指标、单位、场景分组，排序采用实际测量时间；列表保留全部原始数据。
- 同一时刻多个读数均保留，不以时间戳作为唯一键。

### 8.3 提醒执行

提醒业务规则由数据库负责，调度器可随时从规则重建。WorkManager 负责备份、重试与维护，不用周期 Worker 模拟精确定时；官方说明周期任务受约束及系统优化影响，执行时间并不精确。[官方任务定义文档](https://developer.android.com/topic/libraries/architecture/workmanager/how-to/define-work)

使用 AlarmManager 适配目标系统允许的提醒方式：默认支持非精确提醒，确需精确提醒时核验权限、系统能力及发布渠道资格；未获授权时降级并解释。首版不依赖 `USE_EXACT_ALARM` 必然获批。

- 预约无具体时间：让用户选择提醒时刻，不假设午夜通知。
- 调度未来 7 天事件，优先安排最近事件；应用启动、规则变化和维护任务补齐。
- 监听重启、时间/时区变化、版本更新，解锁后从数据库重建；调度 generation 屏蔽旧回调。
- 当地固定时刻随当前时区重新计算，提示时区变化；固定间隔功能延后。
- 夏令时不存在时刻使用当天第一个有效时刻，重复时刻只取一次，并保存计算结果。
- 锁屏仅显示“孕迹提醒”；锁定状态点击“已服用”先认证再提交，不能在认证前写医疗记录。
- 严格模式下密钥不可用时可延期重建，设置页说明重启后需要先打开应用解锁；系统强行停止可能阻止提醒，提供状态检查入口。

## 9. 密钥与本地安全

### 9.1 密钥分层

1. 创建随机 256 位资料库主密钥 VMK，不由用户设备信息派生。
2. 使用成熟密码库的 HKDF-SHA-256 与不同用途标签派生数据库、对象加密和清单密钥，不自写密码算法。
3. 通过本机 Keystore 封装 VMK；数据库密钥、VMK 均不进入 DataStore、日志或源码。
4. 附件使用 AES-256-GCM，随机 96 位 nonce、128 位 tag；每次重新加密生成新 nonce 和新对象 ID。
5. AAD 绑定格式版本、vaultId、objectId 与对象类型；解密时任何认证失败均停止使用该对象。

同一密文对象可在多个快照复用。仅在有意更新对象时生成新密文，禁止覆盖已有对象并复用 nonce。原文文件名、原文哈希和医疗元数据仅存于加密清单中，远端路径使用随机 ID。

### 9.2 恢复密钥与口令

V1.0 必须提供随机 256 位恢复密钥，使用带校验的可抄录编码。恢复密钥通过独立用途派生恢复封装密钥，加密 VMK；它不能与加密备份一同明文上传。

用户启用备份前保存恢复密钥，并完成片段核对。应用说明设备丢失且恢复信息遗失时无法解密。

恢复口令属于有条件功能：P0 若选定成熟 Argon2id 实现并完成兼容、参数基准和低内存测试，则额外提供口令封装槽。记录算法版本、随机盐与参数；恢复前限制可接受参数上限，防止恶意清单耗尽资源。未通过验证则隐藏口令入口，保留恢复密钥路径，不使用裸 SHA-256 代替 KDF。

### 9.3 锁定模式

- 普通模式：应用锁控制界面访问，设备首次解锁后后台可使用受设备保护的密钥执行备份。
- 严格模式：VMK 仅通过要求用户认证的封装路径取得，内存中不再持有时后台延期；重新认证后恢复。
- 切换严格模式时必须移除可绕过认证的本地 VMK 封装，不只改变界面开关；处理切换中断的回退。
- 退出、锁定或恢复时尽量缩短密钥驻留，承认托管运行时无法保证所有内存副本立即擦除。

系统备份排除数据库、密钥封装、附件、草稿、凭据和预览缓存；不依赖 Android 自动备份完成迁移。设备密钥失效时保留加密原件，引导通过恢复密钥重新封装。

## 10. 备份格式与 WebDAV 协议

### 10.1 远端目录

```text
<用户选择目录>/pregnancy-journal/<vaultId>/
├─ vault.json
├─ objects/<随机objectId>.bin
├─ snapshots/<随机snapshotId>.bin
└─ commits/<随机snapshotId>.json
```

`vault.json` 仅含格式版本、vaultId、加密算法及封装后的 VMK 恢复槽，不含明文医疗信息。commit 为可发现入口，包含 snapshotId、密文长度/哈希和带认证标签的提交内容；正文业务计数、时间、原文件名等保存在加密清单内。认证依靠 VMK 派生密钥，不把普通哈希当作防伪签名。

密文大小、对象数量和访问时间等流量元数据无法完全隐藏，在隐私说明中披露。

### 10.2 快照格式

加密清单包含 formatVersion、schemaVersion、vaultId、snapshotId、writerId、writerSequence、capturedSequence、createdAt、业务表数据对象、附件对象引用及其密文/原文校验信息。

快照备份规范化逻辑数据，不直接复制正在写入的数据库/WAL。使用数据库一致性读事务导出逻辑记录与附件引用到加密本地快照，事务结束后再联网上传；附件对象不可变且在任务期间被 pin，清理器不可移除。

每个快照是可独立恢复的完整逻辑视图，附件可共享底层对象。不得要求恢复者持有某次已被清理的增量快照。

### 10.3 上传状态机

`QUEUED → CAPTURING → UPLOADING_OBJECTS → VERIFYING → COMMITTING → COMPLETE`。

可重试失败进入 RETRY_WAIT；认证失效进入 NEEDS_CREDENTIALS；密钥不可用进入 NEEDS_UNLOCK；空间不足进入 NEEDS_SPACE。取消和失败不更新最后成功快照。

具体步骤：

1. 检查当前本机写入资格、密钥可用性与目标目录身份。
2. 生成一致性快照及文件引用清单，记录 capturedSequence。
3. 对新对象使用随机路径上传，重试同一对象时校验已有内容；不覆盖有效对象。
4. 上传加密快照。严格完成校验采用下载密文并核对哈希；仅 HEAD 长度相等不足以认定内容一致。
5. 最后发布 commit；下载回读并验证认证及引用。部分写入或无效 commit 在列表中忽略。
6. 将备份标记 COMPLETE，记录 capturedSequence。期间新增记录保持“待备份”。

commit 是逻辑提交点，不假设 WebDAV 支持跨对象原子事务。普通上传不要求服务器支持原子 MOVE；可选临时上传能力必须实测后启用。

### 10.4 WebDAV 客户端规则

- 仅接受 HTTPS，验证证书，不提供“忽略证书错误”开关。
- 支持有限的 PROPFIND、MKCOL、PUT、GET、HEAD；云端清理单独使用 DELETE。
- 路径分段编码，不直接拼接用户提供的文件名；校验返回路径仍在目标根目录内。
- 禁止向不同源重定向携带凭据；XML 禁用外部实体并限制响应大小和嵌套。
- 401/403 停止盲目重试；404 按对象不存在处理；409 检查父目录；413/配额不足提示用户；429 遵守 Retry-After；网络错误及 5xx 指数退避。
- 目录列表支持 207 Multi-Status，逐项解析成功与失败，不把整体响应码当作所有文件均成功。
- 不默认假设存在 ETag、If-Match、断点续传或锁；能力与服务商限制记录到 P0 报告。

### 10.5 单主设备与换机

恢复到第二台设备后，默认“可使用本地记录、云端自动备份关闭”。用户明确选择“将此设备作为主设备”后，必须提醒旧设备关闭备份。

V1.0 不提供跨设备强制排他锁。采用不可变对象与按 writerId 分支的提交，不允许不同设备覆盖已有有效快照。检测其他 writer 的新提交时暂停本机自动备份和自动云端清理，要求用户确认主设备。

网络分区下不能保证即时检测双主；协议依靠独立分支保全快照，而非宣称完全阻止并发写入。多 writer 状态恢复时展示来源设备与时间，不自动用设备时钟选定唯一“最新”。

### 10.6 调度与保留

本地修改后短延迟合并触发唯一备份任务；大附件默认允许设置仅 Wi-Fi，用户可手动覆盖。应用前台按需检查，周期补偿初始设为约 6 小时，遵循系统调度，不承诺固定执行时刻。

使用唯一 Worker 和资料库级互斥锁防止同设备并发；不为每个字段或附件创建无限任务链。失败保留已上传对象，后续任务复用，不重复上传不变密文。

默认保留最近 7 个日快照与 4 个周快照，并始终保留最近完整可恢复快照。清理前验证所有保留 commit 及引用；先淘汰 commit，再按引用集合清理对象，孤立对象至少保留 30 天。任何列表不完整、校验失败或检测到多 writer 时停止自动云端清理。

## 11. 恢复协议与故障回退

### 11.1 恢复向导

1. 选择本地备份或云端快照，解析格式和大小限制。
2. 输入恢复密钥，或已开放的恢复口令；解封 VMK。
3. 验证 commit、清单与版本；高于当前可支持版本时提示升级，不尝试降级导入。
4. 下载到独立暂存 generation，逐项认证解密、原文哈希校验。
5. 建立独立加密数据库，导入数据并执行关联、枚举、数量、schema 与外键校验。
6. 显示孕期/记录/附件数量、来源设备、时间和完整性预览。
7. 用户确认后，先对当前有效数据生成本地完整加密安全快照；空间不足则不继续替换。
8. 进入维护模式，取消后台任务，关闭数据库及文件句柄，切换 activeGeneration 指针。
9. 打开新库验证，重建设置引用与提醒，保留旧 generation 供回退。

首版不合并已有记录，不导入旧设备 Keystore 封装、通知权限、WebDAV 凭据和设备专用调度 ID。恢复后重新选择当前孕期并确认提醒；自动云端备份默认关闭。

### 11.2 崩溃一致性

以落盘恢复日志保存 PREPARED、SWITCHED、VERIFIED 阶段，并使用经过 P0 验证的原子文件更新 activeGeneration。启动时读取日志：未切换则丢弃暂存；已切换但新库打不开则切回旧 generation。

不对数据库和附件目录做无日志的多次重命名。旧 generation 至少在新库验证完成且用户确认恢复成功后才清理；删除前仍应有可验证的安全快照。

压缩包恢复拒绝路径穿越、符号链接和重复危险条目，限制文件数、单文件大小和总解压大小；远端清单同样限制引用数量与内容大小。

不以“实体每个字段 getter 均有测试”作为目标；重点保护可能造成数据丢失、错误服药记录或密钥泄露的路径。

### 13.2 设备与人工检查

最低支持 API、目标 API 各至少一组模拟器；至少一台实际日用设备与一台低内存设备。另验证目标系统的通知权限、精确闹钟行为、16 KB 页兼容性和厂商后台限制，具体设备型号与 OS 写入验收报告。

人工场景：系统字体 200%、TalkBack、深色、屏幕旋转、应用后台锁定、分享后返回、多页中文摘要、跨月日历、大报告缩放、权限拒绝后恢复。

性能先在 M0/M1 固定设备建立基线，建议初始目标：常规记录保存反馈 P95 ≤ 500 ms；本地首屏内容 P95 ≤ 2 s；大型附件有持续可见进度；任何加密与解析不阻塞主线程。样本至少 30 次，记录冷/热启动及数据规模，达不到时分析后调整，不能把计划目标写成实测结果。

### 13.3 发布阻断条件

- 存在可复现的数据丢失、备份虚假成功、恢复破坏现有数据。
- 存在明文密钥/凭据泄露、认证失败仍使用损坏对象。
- 存在重复服药记录或旧方案继续触发通知。
- 必测迁移路径失败，或采用清库回避迁移。
- 全新设备恢复未通过全部记录数量、关联关系及逐附件原文哈希校验。
- 未解决的崩溃、ANR 或无法操作的核心页面。

## 14. 发布、运维与交付

### 14.1 发布流程

1. 冻结依赖、包名、versionCode、versionName 与备份格式版本。
2. 运行适用的构建、静态检查、单元与设备测试，保存结果；真实 WebDAV 测试使用独立目录。
3. 执行干净安装、上一发布版升级、完整恢复和断网使用回归。
4. 构建签名 release 包；签名密钥及密码在仓库外管理，不输出到日志。
5. 检查 APK 不含测试服务地址、测试凭据、调试日志与不必要权限。
6. 交付安装包、校验值、更新说明、隐私说明、恢复指南和已知限制。

首版无应用服务器，不做运营后台。诊断信息默认本地保存并脱敏，用户主动导出时展示内容范围，不上传医疗记录。

### 14.2 回退策略

应用版本降级不等同于数据格式降级。旧 APK 无法读取新 schema 时不得强行安装回退；保留升级前备份，通过兼容版本恢复。每次发布明确支持的 schema/format 读写范围。

远端故障仅暂停备份；本地功能继续可用。加密格式升级保留旧格式读取能力，完成新备份验证前不清理旧快照。主密钥轮换延后，首版仅支持更新恢复封装；发生密钥泄露需另立迁移方案。
