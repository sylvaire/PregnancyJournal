# 发布流程

## 自动构建 Release APK

`.github/workflows/release-apk.yml` 在**发布 Release** 时自动构建 APK 并作为附件上传。

### 触发方式

| 方式 | 行为 |
|---|---|
| 在 GitHub 上发布 Release（Draft 转为正式发布） | 构建 APK → 运行单元测试 → 上传 APK 与 `.sha256` 到该 Release |
| Actions 页面手动运行 `Release APK` | 只产出构建 artifact，不写 Release 附件 |

手动触发时可填 `tag`，用于给 APK 文件名加前缀。

### 产物命名

```
PregnancyJournal-<tag>-app-release.apk          已签名
PregnancyJournal-<tag>-app-release-unsigned.apk 未签名（仅供内部验证）
PregnancyJournal-<tag>-app-release.apk.sha256   校验值
```

### 配置签名（可选但发布必需）

未配置密钥时 workflow 仍会成功，但产出 **未签名 APK**，无法直接安装到用户设备。
配置后自动产出已签名 APK。

在仓库 **Settings → Secrets and variables → Actions** 添加以下 4 个 secret：

| Secret | 含义 |
|---|---|
| `RELEASE_KEYSTORE_BASE64` | 签名密钥库文件（`.jks`）的 Base64 编码 |
| `RELEASE_KEYSTORE_PASSWORD` | 密钥库密码 |
| `RELEASE_KEY_ALIAS` | 密钥别名 |
| `RELEASE_KEY_PASSWORD` | 密钥密码 |

生成 Base64（本地执行，**不要把 `.jks` 提交到仓库**）：

```bash
base64 -w 0 my-release-key.jks > keystore.b64
# 复制 keystore.b64 的内容到 RELEASE_KEYSTORE_BASE64
```

创建密钥库（如尚未有）：

```bash
keytool -genkeypair -v \
  -keystore my-release-key.jks \
  -keyalg RSA -keysize 4096 -validity 10000 \
  -alias pregnancy-journal
```

> 密钥库文件、密码与恢复密钥一样属于高敏感信息。请离线备份，不要提交、不要上传到
> 公开位置、不要在 Issue/日志中粘贴。丢失签名密钥将无法为已发布应用提供升级包。

### 本地复现同一构建

签名相关环境变量在本地也可用，行为与 CI 一致：

```bash
# 未签名
./gradlew --gradle-user-home .gradle-user :app:assembleRelease

# 已签名
RELEASE_KEYSTORE_PATH=/path/to/my-release-key.jks \
RELEASE_KEYSTORE_PASSWORD=*** \
RELEASE_KEY_ALIAS=pregnancy-journal \
RELEASE_KEY_PASSWORD=*** \
./gradlew --gradle-user-home .gradle-user :app:assembleRelease
```

四个变量齐备且密钥库存在时才会启用签名；缺任一则回退为未签名包（不报错）。

### 版本号

`app/build.gradle.kts` 中的 `versionCode` 与 `versionName` 目前为 `27` / `0.26.0-dev`。
正式发布前需要按版本规划更新，并在阶段记录中留存变更说明。

## 手动发布检查清单

1. `./gradlew --gradle-user-home .gradle-user testDebugUnitTest lintDebug` 通过
2. 在目标设备/模拟器跑一次全量仪器测试
3. 更新 `versionCode` / `versionName` 与 `docs/测试验收报告.md`
4. 在 `docs/阶段记录/` 追加交付记录（含验证证据）
5. 打 tag（如 `v0.26.0`），创建 Release 并发布
6. 确认 workflow 上传的 APK 带签名，核对 `.sha256`
