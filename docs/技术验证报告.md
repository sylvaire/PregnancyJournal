- 本机：Windows、JDK 23.0.1、Gradle 8.13、Android SDK 36.1。
- 测试：独立 API 34 x86_64 模拟器，项目内 AVD，端口5580，不连接个人手机。
- 应用ID：`cn.yunji.journal`；开发版 `0.1.0-dev`，尚非 V1.0 正式版。
- 开发基线：AGP 8.13.2、Kotlin 2.3.20、KSP 2.3.12、Compose BOM 2026.01.01、Navigation 3 1.0.1、Room 3.0.3、SQLCipher 4.19.1、Hilt 2.57.2；已实际编译和测试，不表示 P0 全部门槛通过。

## 已观察到的兼容性证据

1. Room 3.0.3、SQLCipher 4.19.1 官方制品端点返回200，未使用旧版 SupportOpenHelperFactory 初始化 Room 3。
2. Hilt 2.59.2 实际应用插件时报错要求 AGP ≥9，当前基线选择2.57.2。
3. Compose BOM 2026.09.00 / Navigation 3 1.2.0 实际 AAR 元数据要求 API37、AGP ≥9.1；不能与已有8.13工具链直接混用。
4. 仓库中平台编号是 `platforms;android-37.0` 而非 `platforms;android-37`；直接安装后者失败。为减少本次无关工具链升级，改用稳定的兼容 UI 基线，保留 Room3/Navigation3 原生架构。
5. Gradle9分发下载速度低，已停止本项目升级下载。后续工具链升级单独验证，不通过跳过 AAR 检查掩盖问题。
6. Gradle Wrapper 已由已安装Gradle生成，下载源为官方 `downloads.gradle.org`；首次独立 wrapper 下载与本机 Gradle 执行结果分开验证。

7. 首次源代码编译发现驱动正确包名为 `net.zetetic.database.sqlcipher.driver.SQLCipherDriver`；按实际4.19.1制品修正后编译通过，未取消加密。
8. KSP `symbol-processing-aa-embeddable:2.3.12` 的80,992,357字节制品单连接下载停滞。项目脚本从官方 Maven Central 分段下载，检查每段206/Content-Range/长度，合并后比对官方 SHA-256；通过的 JAR/POM 放在项目私有 `.local/maven`，不上传制品到第三方仓库。另一个 Kotlin 编译器制品的 SHA-256 端点404，脚本拒绝完成，该失败产物未作为本地成功制品使用。
9. 本机 MockWebServer 自动生成的 URL 主机名被系统反向解析为另一个域名，导致两项 TLS 测试首次失败；测试显式使用 localhost 后全部通过，未放宽应用证书和主机校验。

本组合先冻结为0.1.0-dev开发基线。工具链升级单独验证，不将“有更新版本”的提示处理成跳过检查。

- 实际 UI 操作已确认建档→首页、预约草稿离开/重启恢复、预约保存/重启后查看、标记就诊后列表显示已完成。

## 当前实现边界

- 数据库 schema1 为 P0/M1 的档案、日期历史、产检、变更队列和草稿；完整 V1.0 业务表后续增加并提供迁移。
- P0 快照标识为 `YJ-P0-1`，只验证加密与逻辑记录往返，不能用作正式全量备份，不暴露用户导出入口。
- WebDAV 只有协议客户端和本地受控 TLS 测试；没有真实坚果云账号验收，不显示“云端备份成功”。
- 当前没有版本迁移历史，schema1→下一版迁移将在变更时用真实旧库测试，不宣称已经完成迁移验证。
- 开发版允许截图以便模拟器视觉核对；release 使用 FLAG_SECURE。未提供应用锁开关前不能把截图限制当作生物识别应用锁。
