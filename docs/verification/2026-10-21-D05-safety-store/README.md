# D05 本机安全副本管理底层

2026-10-21，新增 SafetyCopyStore：仅识别 vault/restore-safety 下非空 UUID.yunji 普通文件；按修改时间和 ID 稳定排序，暴露大小/时间而不解密医疗资料。按 id/大小/修改时间核对用户选中的条目，阻止过期选择删除或复制。删除只操作该文件并同步父目录；流式复制使用64KiB缓冲、取消检查点、长度与元数据复核、SHA256回执，不关闭调用者输出。

任何 restore-journal.json 存在都拒绝管理（包括损坏日志，避免读日志时自动删除后放行）；不接受路径穿越、文件/目录符号链接或目录重定向。进程内所有管理实例共享锁，复制期间不被管理删除。目录系统别名先解析，兼容 Android 的 /data/user/0 与 /data/data；叶目录/文件符号链接仍拒绝。

新增5项JVM：完成文件筛选/复制、过期选择、恢复期间保护、精确删除、取消保留。完整185项JVM0失败，应用/测试构建和lint通过。API34真实目录同步/文件符号链接/目录符号链接专项1项通过（0.039秒），只用随机缓存夹具，正式库与手机资料未操作。

初次JVM删除触发Android系统调用桩，改为可注入目录同步，JVM验证规则，设备用默认真实同步；初次设备发现合法系统目录别名被过严校验拒绝，修复后完整重新构建/单元检查与设备通过。不将失败算通过。

本轮只完成底层；未接用户列表、明确删除确认或SAF导出/回读校验，不能宣称应用安全副本管理已可用。核心复制只是已存密文的逐字节复制，不重新认证恢复内容；独立解密证明见 D05-two-safety。调用方须在IO线程执行，导出需负责空目标检查、回读/失败清理和防重放。旧代际清理、云端下载恢复和严格/中断矩阵继续保留。
