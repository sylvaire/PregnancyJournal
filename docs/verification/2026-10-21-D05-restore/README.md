## 覆盖内容

- 代际布局：旧安装仍使用 `vault/journal.db`；新代际为 `vault/gen/<uuid>/journal.db`，附件对象仍共享 `vault/objects`。指针缺失时按旧布局打开，指针存在但代际数据库缺失时明确报错，不静默新建空库。
- 原子指针：`active-generation.json` 先写临时文件并 fsync，再原子替换并同步目录；失败即中止，不报告成功。指针只含随机 UUID，篡改最多使应用报告不可读，不会串库。
- 恢复向导：读取备份 → 用恢复密钥解密并逐项认证 → 在隔离库中导入并核对 → 复制为暂存代际 → 返回数量/来源/序号预览；写入 PREPARED 后等待用户确认。
- 先校验后切换：确认时写 SWITCHED、原子切换指针、再写 VERIFIED；暂存数据缺失、状态不是 PREPARED 或重复提交都会被拒绝，不会切换到空代际。
- 崩溃一致性：启动先读恢复日志再决定——未切换则丢弃暂存；已切换但新库不可用则回滚到上一代际；无可用上一代际则回退旧布局；回滚后关闭日志，重复启动不再移动指针。
- 回退保留：切换后保留上一代际，`reclaimPrevious` 只在显式回收时删除，且只删旧目录。
