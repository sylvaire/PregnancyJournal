## 覆盖内容

- 保留策略：始终保留最新完整快照；再保留最近7天内每个自然日的最新一份，以及最近28天内每个ISO周的最新一份；其余进入淘汰。窗口以当前时间回推，避免久远资料因“恰好是那一周最新”而无限期占用云端。
- 清理规划：先淘汰提交，再按引用集合处理对象。被任何保留快照引用的对象永不孤立；新孤立的对象只登记不删除；仅当孤立满30天（且服务端最后修改时间也不新于该起点，即对象被重写过则重新计时）才可删除。
- 停止条件：目录列表不完整、存在未通过认证的提交、或检测到其他设备的提交，一律停止自动清理并给出原因。
- 远端适配器：读取前要求身份文件与目录结构已存在，绝不为清理新建备份位置；逐个提交下载清单并做VMK认证后才进入引用集合；删除仅限规范化 `commits/<uuid>.json` 与 `objects/<uuid>.bin`。
- 持久台账：孤立时间写入设备本地，跨进程重启保留；重复登记不延长宽限期；上限5000条并按时间保留最新。
- 接入唯一任务：上传成功后最多每24小时清理一次；检测到其他设备时暂停；清理失败不影响已成功的备份，也不会紧循环重试。
