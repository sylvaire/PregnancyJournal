# E01 系统通知总开关的跨进程往返

- 日期：2026-10-23；设备：专用 `PJ_API36_16K` 模拟器，API36/16KiB；手机无线调试当时未连接。
- 产品调整：提醒设置页始终显示“系统通知设置”，让已允许通知的用户也能直接管理系统开关。
- 首次尝试在单一仪器测试中关闭再开启通知时，Android 在关闭后以 `PermissionHelper` 主动终止应用/测试进程；[中断日志](device-test.log) 是**未通过**的原探针，已从正常测试中移除。随后按真实进程边界拆为三段：应用内从已允许状态打开系统设置 [1/1](open-allowed.log)；系统开关关闭后重新启动应用，确认页面显示未允许 [1/1](after-off.log)；系统开关重新开启后再启动应用，确认页面显示已允许且实际发出测试通知 [1/1](after-on.log)。三段均无跳过。
- 主机通过 Android 设置界面的可见总开关操作，关闭后 XML 检查为 `checked=false`，重新开启后 `checked=true`；没有通过 `pm grant/revoke` 替代系统界面。结束时开关恢复开启，测试通知取消，应用进程停止。
- 边界：仅覆盖专用模拟器的系统设置结构；小米/OEM 设置页、真实后台限制、锁屏呈现仍待验证。
