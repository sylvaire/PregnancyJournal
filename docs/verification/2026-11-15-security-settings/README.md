# 安全设置真机报错修复

日期：2026-11-15。当前用户报告路径已修复并在小米11Ultra复验；不等同所有安全功能验收。

## 问题与修复

手机尚未设置安全锁屏，开启严格模式时先创建需要用户认证的密钥，后检查认证能力。创建失败的厂商异常被原样显示，设置尚未成功却停留在锁定页。

修复为先检查安全锁屏与认证能力，再覆盖会话/准备密钥；条件不满足时在安全设置页显示中文原因。后续认证失败仅在原有策略仍允许访问时返回设置，否则保持锁定。原始异常不直接展示，未认证的通知动作不写入。

- [最终构建](build.log)：默认安全Debug及设备测试构建、完整JVM/lint成功52s；60类371项JVM无失败，lint0错误31警告。
- [最终模拟器5/5](emulator-result.txt)：真实Main设置路径1项、AccessState策略4项实际通过；新增设置检查确认两个开启按钮只提示，原开关和已提交密钥文件字节不变，并可返回及重建。
- [隔离安全检查](isolated-security-result.txt)：报告17项，实际15通过、2项按凭据/运行参数条件跳过。未测试的严格认证场景不计通过。
- [手机操作摘要](phone-result.txt)：覆盖安装成功，重试严格模式与应用锁均显示中文原因，停留设置页，不显示原英文异常，不误切到锁定页，可返回我的；原应用锁开关和时限不变。
