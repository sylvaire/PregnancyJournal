# 决策备忘：Timeline（孕期时间线）信息架构差异

- 日期：2026-10-24
- 背景：UI 逐屏评审（`docs/verification/2026-10-24-figma-ui-alignment/comparison/README.md` §8 P0-5、§6）发现实现侧 Timeline 与 Figma 设计屏 12 Timeline 存在**信息架构级**差异，无法只靠样式修复收敛，需要产品/设计决策。
- 状态：**已确认并实现（方案 A，2026-10-24）**。实现与验证见 `docs/verification/2026-10-24-timeline-ia-a/README.md`；设计口径补充：保留所有事件类型作为「全部」视图记录行，仅收敛筛选为 全部/产检/日常；CTA 文案「写一条日常备注」。

## 1. 现状对比

| 维度 | Figma 设计（12 Timeline） | 当前实现（TimelineScreens.kt） |
|---|---|---|
| 主体形态 | 72 dp 记录行 + 44 dp 图标容器；按日期分组、右侧显示孕周 | 大卡片信息流（JournalCard） |
| 备注表达 | 杏色备注卡（`#FAEAD8` 底 / `#80582C` 字） | 卡片正文 + 次要色文本 |
| 筛选体系 | 全部 / 产检 / 日常 | 全部 / 产检 / 资料 / 方案变更 / 服药（`TIMELINE_TYPES`，与记录枢纽一致） |
| 底部操作 | 底部主 CTA（如“写日常记录”） | 顶部 `JournalButton("写日常记录")` |
| 数据来源 | 设计仅示例产检/日常 | 实现额外聚合资料导入、用药方案变更、服药事件（与备份/资料/用药模块共用时间线） |

## 2. 可选方案

### 方案 A：实现回改（严格按设计重做 Timeline）
- 做法：72 dp 记录行 + 日期分组/孕周 + 杏色备注卡 + 筛选收敛为 全部/产检/日常 + 底部 CTA；资料/方案变更/服药事件从 Timeline 移除或降级到各自模块。
- 优点：与设计稿 100% 对齐；信息密度高、符合 Figma 基准。
- 代价：**丢失三类事件的时间线可见性**（用户可能依赖“资料/方案变更/服药”在时间线中的上下文）；需同步改导航/筛选/测试与空态；开发量中-大。

### 方案 B：设计稿回改（以实现为准更新 Figma）
- 做法：保持实现（大卡片信息流 + 四类筛选 + 顶部 CTA），更新 Figma 12 Timeline 画板以覆盖现状，并补“资料/方案变更/服药”三类事件的卡片范式。
- 优点：零实现风险；保留现有信息架构与测试；设计稿成为真实基线。
- 代价：需要设计投入；与“设计先行”的初始目标略有偏离（设计稿将反映既有实现）。

### 方案 C：折中（推荐）
- 做法：视觉层面向设计靠拢——记录行高度/图标容器、日期分组 + 孕周、杏色备注卡、底部 CTA；**保留**现有四类筛选（全部/产检/资料/方案变更/服药），并把“筛选 IA”作为一个设计稿需补充的画板项；资料/方案/服药事件以紧凑行呈现。
- 优点：拿到设计稿 80% 的视觉一致性，同时不牺牲现有信息完整性；改动集中在 TimelineScreens 与设计稿补充。
- 代价：设计稿与实现仍有“筛选维度”差异，需在交付说明中标注；开发量中。

## 3. 建议
- 若以 **Figma 为唯一设计基准**：选 A（但需确认资料/方案/服药事件是否可从 Timeline 移除）。
- 若以 **现有用户价值/信息完整性优先**：选 C（推荐），随后请设计侧补“四类筛选 + 资料/方案/服药卡片”画板。
- B 仅在“设计稿需要快速与现状同步”时采用。

## 4. 需用户确认的问题
1. Timeline 是否必须保留「资料 / 方案变更 / 服药」三类事件？（决定 A 是否可行）
2. 若选 C：日期分组/孕周、杏色备注卡、底部 CTA 是否按设计全部实现？
3. 设计稿是否可由设计侧回改（方案 B/C 的前置）？
