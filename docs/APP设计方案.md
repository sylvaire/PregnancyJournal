# 「孕迹」Android APP 完整设计方案

**文档版本：V1.0**  
**产品形态：原生 Android 应用**  
**核心方向：孕期档案、产检资料、用药记录、健康管理、本地加密与坚果云备份**

---

## 一、产品定位

「孕迹」是一款以个人孕期档案为中心的记录工具，帮助用户把分散在相册、纸质检查单、医院小程序和聊天记录中的资料，整理为连续、可检索、可备份的孕期时间线。

产品围绕三个日常问题展开：

1. **今天需要做什么**：查看产检预约、待办事项和用药提醒。
2. **过去发生了什么**：回顾检查结果、用药情况和健康指标。
3. **资料是否安全**：确认本地保存、云端备份和换机恢复状态。

首版面向个人及家庭使用，不要求注册应用账号；未连接坚果云时，核心记录功能仍可完整使用。

### 1.1 目标用户

| 用户 | 主要需求 |
|---|---|
| 孕期记录者 | 管理孕周、产检、报告、用药和身体变化 |
| 陪诊伴侣或家人 | 协助整理资料、了解预约安排 |
| 有多次孕期记录需求的用户 | 将不同孕期分开保存并长期归档 |
| 重视隐私的用户 | 本地保存、自选云盘、控制资料导出 |

### 1.2 产品原则

- **先保存，再同步**：每次操作首先写入本地。
- **重要状态可见**：清楚区分已保存、待上传、上传失败和已备份。
- **尽量少填**：允许先存报告，稍后补齐分类和说明。
- **保留原始资料**：OCR 和人工摘要均关联原件。
- **帮助记录与沟通**：不自动诊断，不推荐药品或调整剂量。
- **让用户掌握数据**：支持导出、恢复和删除。

## 三、信息架构

采用四个底部入口，控制一级页面数量。

| 一级入口 | 页面内容 | 高频操作 |
|---|---|---|
| 今天 | 孕期概览、今日待办、下次产检、近期记录 | 新增记录、确认服药 |
| 产检 | 预约列表、历史产检、日历视图 | 新建预约、补充就诊记录 |
| 记录 | 资料、用药、健康、孕期时间线 | 导入报告、记录指标 |
| 我的 | 孕期档案、备份、安全、导出、设置 | 切换孕期、立即备份 |

“记录”页内部使用分段导航，不额外增加底部入口。

通用新增菜单包括：

- 产检预约
- 检查资料
- 用药方案
- 健康指标
- 日常备注

从具体页面进入新增时，默认选择对应类型，并自动带入当前孕期。

## 四、关键用户流程

### 4.1 首次使用

打开应用 → 阅读简短隐私说明 → 创建孕期档案 → 进入首页。

创建时填写：

- 档案名称，可使用默认名称；
- 末次月经日期或医生确认的预产期，至少提供一项；
- 可选备注。

进入首页后，通过可跳过的引导逐步设置应用锁、通知和云端备份，避免首次启动连续索取权限。

日期尚不确定时允许先建立档案，首页显示“待补充孕期日期”。

### 4.2 一次完整产检

创建预约 → 设置提醒 → 到院后记录就诊情况 → 拍照或导入报告 → 关联本次产检 → 添加医生建议与下次预约。

预约本身保留，完成后转为历史就诊记录，不要求重新填写一遍。

### 4.3 快速保存报告

点击新增资料 → 选择拍照、图片或 PDF → 本地保存 → 补充标题和日期 → 选择是否关联产检。

分类、医院、备注均为选填。文件保存成功与云端上传成功分别提示。

### 4.4 换机恢复

安装应用 → 选择恢复已有数据 → 连接坚果云或选择本地备份 → 输入恢复口令 → 校验内容 → 展示恢复预览 → 确认恢复。

恢复预览显示孕期数量、记录数量、附件数量、备份时间和完整性结果。

## 五、页面与功能设计

### 5.1 首页「今天」

页面按以下顺序展示：

1. 当前孕期名称与切换入口；
2. 孕周卡片；
3. 今日待办；
4. 下一次产检；
5. 快捷记录；
6. 最近新增资料；
7. 简洁的数据保护状态。

孕周卡片显示“孕 18 周 + 3 天”等信息，以及采用的日期依据。用户修改预产期后，应能查看变更说明。

首页优先呈现可执行事项，不加入信息流广告和大量泛科普内容。

**空状态**

- 没有预约：提供“添加下一次产检”。
- 没有报告：提供“保存第一份检查资料”。
- 今日无待办：显示平静的完成状态。
- 尚未备份：显示可关闭的设置入口。

### 5.2 孕期档案

支持多个档案，默认进入最近使用的进行中档案。

字段包括档案名称、末次月经日期、确认预产期、预产期来源、建档医院、备注和状态。

状态分为：

- 进行中；
- 已结束；
- 已归档。

结束档案时允许只记录结束日期，不强制填写原因。历史档案可查看和补录，提醒默认停止。

**日期规则**

- 医生确认的预产期优先用于展示；
- 只有末次月经时，展示基于常规 280 天的估算，并标明“估算”；
- 用户修改日期时记录历史版本；
- 历史产检保留当时记录的孕周及其依据，避免日期修改后失去原始上下文；
- 超出常规展示范围时仍允许记录，不输出异常诊断。

### 5.3 产检管理

默认展示“待进行”和“历史记录”，日历作为切换视图。

**预约字段**

| 字段 | 要求 |
|---|---|
| 日期 | 必填 |
| 时间 | 可选，未填写时显示“时间待定” |
| 医院、科室、医生 | 选填 |
| 检查项目 | 多项文本 |
| 准备事项 | 用户自行填写 |
| 提醒 | 可设置多个提前时间 |
| 备注 | 选填 |

不根据项目名称自动断言是否需要空腹等准备事项。

**详情页**

展示预约信息、实际就诊日期、检查项目、关联报告、医生建议、相关用药和后续安排。

状态包括待进行、已完成、已取消。日期已过仍未确认的预约显示“待确认”，由用户决定是否完成或改期。

### 5.4 检查资料

**资料类型**

超声、检验、筛查、处方、病历、费用凭证及其他。

**组织方式**

一份“资料”可包含多张图片或多个文件，支持调整图片顺序、修改封面，并关联一次产检。

**基础功能**

- 系统图片选择；
- PDF 文件导入；
- 拍照导入；
- 图片缩放与旋转；
- PDF 翻页；
- 标题、日期、类型和备注编辑；
- 按孕期、日期、类型、医院筛选；
- 按标题和备注搜索；
- 导出、分享、删除和恢复。

导入后复制到应用私有存储，原相册文件被删除不应影响已归档资料。

**OCR 扩展**

原件先保存，识别在后台进行。识别结果标为“待核对”，用户确认后才可转换为健康指标或其他结构化记录。

数值、单位、参考范围与来源页必须保留关联。低置信度内容不自动填入关键字段。

### 5.5 用药管理

分为药品、用药方案和实际服药三层。

| 层级 | 主要内容 |
|---|---|
| 药品 | 名称、规格、剂型、包装照片 |
| 用药方案 | 医嘱来源、每次剂量、单位、频次、起止日期 |
| 服药记录 | 计划时间、实际时间、实际剂量、状态、备注 |

频次支持每天固定时间、每周指定日期、临时一次和按需服用。

复杂医嘱允许只保存原文，暂不生成自动提醒，避免错误解析。

**服药交互**

通知提供“已服用”“稍后提醒”，详情页支持“跳过”和“补记”。

漏记不会自动变成漏服；补记可以调整实际服药时间。修改方案保留历史，暂停方案仅取消未来提醒。

界面不展示鼓励补服、加倍服药或自行停药的建议。

### 5.6 健康记录

首版提供：

- 体重；
- 血压及可选心率；
- 血糖及测量场景；
- 症状、心情与日常备注；
- 自定义指标。

每条记录保存数值、单位、实际测量时间、录入时间、来源和备注。

血糖需区分空腹、餐后时长或其他场景，不将不同场景混为同一条趋势。

**趋势页**

支持时间范围、孕周视角、原始数据列表和点选详情。缺失数据保留空缺，不补为零。

首版展示记录与趋势；个性化目标范围如需提供，由用户录入并标注来源。

### 5.7 孕期时间线

按发生日期整合产检、资料、用药变更、健康记录和日常备注。

支持按类型筛选，点击进入原始记录。日期明确而时间不明的事件按日期展示，不伪造具体时间。

## 六、提醒设计

| 提醒类型 | 触发依据 | 完成方式 |
|---|---|---|
| 产检 | 预约日期及用户选择的提前量 | 完成、取消或改期 |
| 用药 | 当前有效方案 | 已服用、跳过、补记 |
| 自定义 | 用户指定日期或时间 | 标记完成 |
| 备份问题 | 持续失败或需要重新授权 | 修复连接后解除 |

规则包括：

- 在用户首次创建提醒时申请通知权限；
- 拒绝权限后保留应用内待办，并展示可恢复入口；
- 锁屏通知默认隐藏药名、医院和检查结果；
- 处理设备重启、时间修改和时区变化；
- 用药计划明确采用“当地固定时刻”还是“固定间隔”，避免出行时重复提醒；
- 不承诺系统限制下百分之百准时送达。

同步任务与定时提醒分别实现，正式开发时核验目标 Android 版本的调度与权限要求。

## 七、视觉与交互规范

### 7.1 整体风格

采用 Material 3，以温暖、安静、清楚为主要方向。

建议使用暖白背景、柔和绿色主色和少量暖杏色点缀。正文保持高对比度，颜色不承担唯一的信息表达。

减少装饰性插画，把空间留给日期、数值、报告缩略图和操作按钮。

### 7.2 基础规范

| 项目 | 设计要求 |
|---|---|
| 页面边距 | 通常 16 dp |
| 间距体系 | 4、8、12、16、24、32 dp |
| 点击区域 | 至少 48 dp |
| 正文 | 通常 16 sp，支持系统字体放大 |
| 表单 | 必填项少、错误就近说明 |
| 深色模式 | 支持系统跟随与手动选择 |
| 无障碍 | 图标有描述，状态同时使用文字和图形 |

### 7.3 操作反馈

- 记录成功：“已保存到本机”。
- 上传未完成：“已保存，等待备份”。
- 网络失败：“本机资料可正常使用，稍后重试”。
- 删除成功：提供撤销入口。
- 附件导入中：显示逐项进度与失败原因。

长表单保留草稿，切换页面、旋转屏幕或进程重建后可以继续编辑。

## 八、数据模型

### 8.1 核心实体

| 实体 | 关键字段与用途 |
|---|---|
| Pregnancy | 孕期名称、日期依据、状态 |
| PregnancyDateRevision | 日期修改历史及生效时间 |
| PrenatalVisit | 预约、实际就诊、项目、建议 |
| Document | 资料标题、分类、发生日期 |
| DocumentFile | 文件标识、格式、顺序、大小、校验值 |
| DocumentVisitLink | 资料与产检的关联 |
| Medication | 药品基础信息 |
| MedicationPlan | 医嘱、剂量、频次、有效期、版本 |
| MedicationIntake | 计划时刻、实际时刻、状态 |
| HealthMeasurement | 指标类型、数值、单位、场景 |
| JournalEntry | 症状、心情和备注 |
| Reminder | 关联对象、触发规则、调度状态 |
| SyncChange | 待同步操作及对象版本 |
| SyncState | 设备游标、错误与同步状态 |
| BackupHistory | 快照版本、时间、完整性结果 |

### 8.2 通用规则

- 业务对象使用全局唯一 ID；
- 孕期业务记录关联 `pregnancyId`；
- 保存创建时间、修改时间与版本；
- 业务修改与待同步变更在同一数据库事务提交；
- 附件采用独立文件存储，数据库保存元数据；
- 日期使用日期类型，时间点另外保存时区语义；
- 删除采用软删除，并保留同步所需的删除标记。

资料删除不连带删除产检；产检删除时，关联资料默认保留并解除关联。

## 九、本地架构与技术方案

采用 Kotlin、Jetpack Compose、Material 3、ViewModel、StateFlow、Repository 和本地数据库构建原生应用。

界面读取本地数据；网络变化由后台流程写入本地后再更新界面。这符合 Android 官方的离线优先架构建议。[参考：Android 离线优先架构](https://developer.android.com/topic/architecture/data-layer/offline-first)

| 层级 | 职责 |
|---|---|
| UI | 页面、组件、输入与展示 |
| Presentation | 页面状态、事件处理、草稿恢复 |
| Repository / 业务层 | 日期计算、记录规则、数据组合 |
| Local Data | 数据库、加密附件、设置 |
| Background | 导入、备份、同步、清理 |
| Remote | WebDAV 请求与远端对象管理 |

首期使用一个 `:app` 模块，按业务分包，后续根据复杂度拆分同步和安全模块。

**依赖决策**

原材料中的 Room 3、Navigation 3、Compose BOM、SQLCipher 和 SDK 版本暂作为候选，实施前建立兼容矩阵并锁定依赖。Room 与 SQLCipher 的驱动组合须通过实际样例验证。

先完成以下技术验证：

1. 加密数据库创建、读写与迁移；
2. 图片/PDF 加密存取；
3. 备份上传与新设备恢复；
4. 应用锁开启时后台任务的可用性；
5. 目标设备与系统版本兼容性。

## 十、坚果云备份与同步

### 10.1 首版采用单主设备备份

首版允许一个主设备写入云端备份。其他设备通过恢复取得数据，不默认开启同时编辑。

连接流程：

填写服务地址与凭据 → 测试访问 → 选择目录 → 设置恢复口令 → 完成首次备份 → 检查备份内容。

连接既有目录时，先识别已有资料库，避免创建空库覆盖历史数据。

### 10.2 备份内容

- 带版本的数据清单；
- 结构化业务记录；
- 加密附件；
- 加密后的恢复密钥信息；
- 文件大小与校验信息；
- 快照创建时间和格式版本。

同步与备份分别显示状态。同步可能传播误删，独立历史快照负责找回旧数据。

建议初始策略为保留最近 7 个日快照及 4 个周快照；未变化的附件复用加密对象，避免重复上传。

### 10.3 原子提交与完整性

先上传附件及数据对象，全部校验成功后，再发布可恢复快照清单。

上传中断时，不把半成品显示为完整备份。清理任务仅删除不被有效快照引用、且超过安全保留期的对象。

### 10.4 多设备同步扩展

后续同步使用对象版本、设备标识、操作 ID 和增量变更，不直接双向覆盖数据库文件。

冲突策略：

- 不相关对象分别同步；
- 同一对象的并发修改保留冲突版本；
- 删除与编辑冲突进入用户确认；
- 重复操作幂等处理；
- 不只依赖设备时间判断覆盖顺序。

WebDAV 缺少可依赖的条件写入能力时，限制为单写入设备，或采用经过验证的追加式变更协议。

## 十一、安全与隐私

### 11.1 本地保护

- 数据库使用经过兼容性验证的 SQLCipher；
- 附件使用认证加密，独立随机 nonce；
- 本地密钥由 Android Keystore 保护；
- WebDAV 凭据加密保存；
- 缩略图、临时预览文件纳入保护与清理；
- 日志排除药名、检查结果、凭据及敏感路径。

应用锁支持生物识别或设备凭据。默认在离开应用一段时间后重新锁定，近期任务预览隐藏敏感内容。

### 11.2 跨设备恢复

设备 Keystore 密钥不能作为唯一恢复手段。

设计独立资料库主密钥：

- 本机通过 Keystore 封装；
- 备份通过恢复口令或恢复密钥封装；
- 新设备解密后，重新用自己的 Keystore 保护。

启用备份时要求用户确认已保存恢复信息。口令与恢复密钥均丢失时，应用无法解密备份。

### 11.3 后台任务与应用锁

应用锁与密钥使用策略分别设计。

普通模式允许设备首次解锁后执行后台备份；严格模式要求用户验证后才能访问密钥，后台任务因此可能延期。设置页明确说明两者影响。

### 11.4 导出与共享

分享报告使用临时授权，用户确认后才向目标应用交付文件。

家庭只读共享后续使用独立共享空间和权限模型。把同一份 WebDAV 凭据交给家人，不能实现可靠的只读控制。

## 十二、导出与恢复

提供三种输出：

| 输出 | 适用场景 |
|---|---|
| 就诊摘要 PDF | 就医时展示近期产检、用药与指标 |
| 原始资料包 | 保存或转交报告原件 |
| 完整加密备份 | 长期保存与换机恢复 |

摘要由用户选择日期范围和内容，并标注“用户整理记录”，附生成日期和来源说明。

恢复默认先导入临时空间，完成解密、格式兼容和附件校验后再替换本地数据。已有数据时，替换前生成本地快照。

首版以完整恢复为主，不自动合并两份未知来源的数据。

## 十三、异常与可靠性设计

| 异常 | 预期行为 |
|---|---|
| 无网络 | 核心功能可用，变更进入等待队列 |
| 云端认证失败 | 保留本地数据，提示更新凭据 |
| 云端空间不足 | 暂停上传，显示未完成数量 |
| 文件导入中断 | 已完成项保留，失败项可重试 |
| 本机空间不足 | 不创建虚假成功记录，明确提示 |
| PDF 损坏 | 标记无法预览，允许导出或替换 |
| 进程被结束 | 已保存内容保留，草稿可恢复 |
| 数据库迁移失败 | 保留原库，禁止自动清空 |
| 恢复中断 | 不破坏当前有效资料库 |
| 通知权限关闭 | 应用内待办继续可见 |
| 密钥失效 | 进入恢复流程，不静默重置资料库 |

## 十五、验收标准

### 15.1 核心功能

- 飞行模式下可新增、查看、编辑和删除核心记录。
- 报告导入后，删除相册原件仍可查看已归档文件。
- 产检预约可转为就诊记录，并关联多份资料。
- 用药方案修改后保留历史，未来提醒正确重建。
- 不同孕期的数据与提醒相互隔离。
- 进程重建后关键表单草稿可继续编辑。

### 15.2 数据保护

- 数据库与附件无法作为明文直接读取。
- 上传中断不会生成“完整备份成功”的状态。
- 全新设备可恢复记录及全部附件。
- 错误口令、损坏备份和恢复中断均不破坏现有资料。
- 备份恢复通过数量与逐文件完整性校验。
- 数据库升级不得以清空数据作为失败处理。

### 15.3 提醒与体验

- 权限关闭、设备重启和时区变化有明确处理。
- 已服用操作不重复生成服药记录。
- 字体放大后主要页面可操作。
- 空状态、加载、失败、重试和删除撤销均完整。
- 以约定测试设备验证冷启动、长列表和大型 PDF，建立可重复的性能基线。

## 实施衔接说明

以上保留对话中的完整设计方案。为消除执行歧义，具体落地以 [V1.0 详细实施文档](V1.0详细实施文档.md) 中标明的规则为准：

- 历史服药和产检保留原始日期依据及方案版本。
