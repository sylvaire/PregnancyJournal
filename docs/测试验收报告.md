### 4.2 API36 上的一项夹具差异

`NavigationExperienceTest.pdfNavigationMetadataSearchAndBackgroundCleanup` 在 API36/16KB 设备上失败：向资料搜索框注入文本后，搜索框状态未变为“不存在”，因此空态“没有匹配的资料”未出现。同一测试在 API34 上通过；两设备默认输入法相同。已排除：崩溃、数据库错误、权限问题、IME 缺失。结论：**这是该测试在 API36 上的输入交互问题，尚未定位根因**；产品搜索逻辑在 API34 与仓储层测试中通过。该项保留为 E01 未决项。

另一项 `scheduledIntakeEditDeleteUndoAndManualHistoryKeepOriginalPlan` 在整轮运行时超时，单独复跑通过，判为负载偶发（不计入通过）。

**2026-10-22 全量复核（API26 兼容性修复后构建）**：API36/16 KiB 页设备全量 `am instrument` 292 项执行、291 通过、0 错误、1 失败（554.7s，证据 `verification/2026-10-22-API36/`），唯一失败仍是上述 `scheduledIntakeEditDeleteUndoAndManualHistoryKeepOriginalPlan`：`ComposeTimeoutException: Condition still not satisfied after 10000 ms`（等待保存服药后的 `all_intakes` 计数）。同一构建下整类运行 `OK (23 tests)`、干净应用数据下单用例 `OK (1 test)`；把 `LockEntryMatrixTest` 或 `MainRestorePickerTest` 与目标用例串行可复现，其余类串行不复现，说明它依赖套件运行顺序/进程级状态，而不是产品写入缺陷（失败时编辑页仍在、已输入剂量仍在、数据库无半条记录）。曾尝试点击后静置 400 ms 或改为等待产品「已保存到本机」反馈，复现率从约 1/2 降到约 1/6 但未确定性消除，故未保留改动。该用例在本次改动之前已是已知偶发（本条首段记录）；当时**保留为 E02 发布前必须修复或隔离的遗留项**，不据此宣称 API36 全绿。**2026-10-23 已定位为测试同步缺陷并修复，见 4.3。**

### 4.3 服药保存用例顺序敏感 flake 闭环（2026-10-23）

**结论：测试同步缺陷，非产品写入缺陷；已修复并全量复核。**

- 根因：Compose 通过 insets API 异步请求软键盘，输入法进程冷启动或系统负载时 `onRequestShow → onShown` 实测可延迟约 1.36 s；测试输入剂量后仅 `waitForIdle()+350 ms` 就滚动并点击“保存服药记录”，键盘恰在此期间出现，`imePadding()` 压缩表单视口，保存按钮滑到键盘窗口下方，真实触摸被键盘窗口接收或落点失效，保存回调未执行，随后 10 s `all_intakes` 等待超时（或点击前 `assertIsDisplayed` 失败）。失败现场语义树（滚动视口被压到 y=296..634、按钮未裁剪坐标 y=946..1083）与 IME 时间线均已留证。顺序敏感性来源：只有“进程内首次触发键盘/输入法被回收”时延迟才超过 1 s，输入法预热后连续通过，故历史现象为“整类/单独跑通过、与其它类串行时更易复现”。
- 修复（仅测试代码 1 个文件 `NavigationExperienceTest.kt`）：新增 `clickSaveAfterKeyboardSettles(label)`——先主动 `hide(ime)`，轮询等待 IME 可见性与保存按钮 `boundsInRoot` 连续 700 ms 稳定（15 s 上限、超时抛出自描述诊断），再 `performScrollTo()` + `assertIsDisplayed()` + 真实 `performClick()`。用于有失败证据的 5 处保存点击（服药保存 3 处、日常记录保存 2 处）。**未改生产代码、未放宽产品断言、未改断言语义。**
- 验证：①冷输入法 + `LockEntryMatrixTest` 串行前置后目标用例连续 3/3 轮 `OK (7 tests)`；②`NavigationExperienceTest` 整类 `OK (23 tests)`（214.6 s，首次整类尝试因 Compose 框架 teardown 崩溃，与本改动无关，重跑通过）；③API36/16KiB 全量 `am instrument` 两轮各 **`OK (338 tests)`、0 失败 0 错误、61 项前置条件跳过**（round2 首跑在 current=232/338 处因模拟器进程退出中断，按环境中断记录，冷启动 AVD 后重跑通过）；④JVM **56 类 / 342 项 / 0 失败 0 跳过**（强制重跑）、lint **0 错误 / 27 警告**（无新增告警）。Lead 复核：重新安装当前 APK 后冷输入法串行 1 轮 `OK (7 tests)`（33.0 s）。
- 证据：[verification/2026-10-23-E02-flaky-intake-test](verification/2026-10-23-E02-flaky-intake-test/README.md)（基线/修复/全量日志、logcat、JUnit XML、设备读回）。
- 边界：只修复有失败证据的两条用例路径，其余“先输入后保存”用例仍使用旧 `settle()`（冷输入法+重负载下理论同类风险，未扩大改动面）；真机/OEM 与第三方输入法未覆盖；模拟器长跑仍可能环境中断，不折算为通过。
